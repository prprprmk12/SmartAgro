# SmartAgro AI Advisor

Веб-dashboard для мониторинга полей Акмолинской области, прогноза урожайности, климатических рисков и экономики хозяйства.

## Запуск

```powershell
npm install
npm run dev:full
```

Команда запускает frontend и MongoDB API одновременно. Откройте `http://localhost:5173/`.

Можно запускать отдельно:

```powershell
npm run server   # API и MongoDB на http://localhost:3001
npm run dev      # frontend на http://localhost:5173
```

Production-проверка:

```powershell
npm run build
```

## Публикация на Railway

Один Railway-сервис запускает Express API и отдаёт собранный frontend с того же домена. Отдельный frontend-сервис и `VITE_API_URL` не нужны.

1. Создайте проект Railway из репозитория и добавьте в него MongoDB (или используйте доступную извне MongoDB).
2. Для сервиса приложения в **Variables** задайте `MONGODB_URI` ссылкой на строку подключения базы, например `${{MongoDB.MONGO_URL}}` (название сервиса и переменной уточните в Railway). Задайте `NODE_ENV=production` и при необходимости `MONGODB_DB=smartagro`.
3. Для текущей карты установите `VITE_YANDEX_MAPS_API_KEY` **до сборки**. Без этого ключа карта в нынешней версии не загрузится. Не размещайте в `VITE_` секретные ключи: они попадают в браузер.
4. Опционально укажите `OPENAI_API_KEY` и `OPENAI_MODEL`. OpenAI-ключ используется только сервером.
5. Railway прочитает `railway.json`: выполнит `npm ci && npm run build`, затем `npm start`. В разделе **Networking** сгенерируйте публичный домен. Проверьте главную страницу и `https://<домен>/api/health` (режим `mongodb`).

После регистрации поля и расходы сохраняются в MongoDB выбранного ТОО. При повторном входе с другого устройства они загружаются через `/api/fields`. Для существующих регистраций после обновления приложения требуется войти снова, чтобы получить серверную сессию. Локальные поля, ранее записанные в браузер, автоматически не переносятся.

Проверка API полей и разграничения доступа: `npm test`.

Порт Railway передаётся через `PORT` автоматически. В production сервис не запустится без MongoDB или собранного frontend; временная база в памяти остаётся только для локальной разработки. `MONGODB_URI` и `OPENAI_API_KEY` нельзя добавлять в frontend или публиковать в репозитории.

## Что работает в demo

- dashboard хозяйства и 6 полей;
- схема карты с зонами NDVI, переключатель NDVI/NDWI/истинный цвет;
- отображение выбранного слоя на полигонах карты и подсказка с назначением индекса;
- прогноз урожая и KPI;
- график динамики NDVI;
- прогноз погоды на 7 дней;
- климатические риски Акмолинской области;
- календарь решений и отметка задачи;
- экономический сценарий с пересчетом маржи при изменении стоимости топлива;
- блок оптимизации на главной странице с расчетом потенциальной экономии топлива и рекомендациями;
- AI Smart Farm Insight с объяснением факторов и доверительным интервалом.
- интерактивный AI-чат: ввод вопроса, история сообщений, подсказки и ответы OpenAI;
- тематическое ограничение AI только для агрономической работы.
- динамическое количество полей и площади выбранного ТОО;
- запрос геолокации после входа для точного центра карты и поиска рядом с хозяйством.

Текущая версия работает на локальном demo dataset и не требует API-ключей.

## Авторизация и MongoDB

До входа приложение показывает отдельный экран авторизации. Можно зарегистрировать агронома, выбрать демо-ТОО и открыть найденные поля на карте либо продолжить без регистрации в demo mode.

Файл `.env.example` подготовлен для настройки. URI используется только backend; его нельзя размещать во frontend или коммитить в git.

Локальный backend уже подключается к MongoDB, автоматически создает базу `smartagro`, добавляет три demo-ТОО и их поля, а также поддерживает регистрацию и вход. Количество полей на dashboard считается из MongoDB, поэтому оно не должно быть фиксированным. Сейчас геолокация устройства центрирует карту и показывает маркер. Для точного отображения всех реальных полей нужно загрузить в MongoDB их GeoJSON/кадастровую геометрию; AI не заменяет геоданные и не используется для выдумывания границ.

## Следующий этап: OpenAI

Ключ нельзя размещать во frontend-коде. После добавления backend-слоя он будет храниться в переменной окружения:

```env
OPENAI_API_KEY=...
```

Frontend будет обращаться только к backend endpoint `/api/ai/chat`. Demo fallback сохранится для запуска без ключа.

AI endpoint уже подключен. Агент получает контекст demo-поля и отвечает на вопросы об урожайности, NDVI/NDWI, погоде, рисках, сроках сева/уборки и экономике. Вопросы вне работы хозяйства автоматически отклоняются.
