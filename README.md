# SmartAgro AI Advisor

Веб-dashboard для учёта полей Акмолинской области, просмотра погоды, индексов и затрат хозяйства. Индексы можно получить по запросу из CDSE или загрузить из CSV. Автоматическое обновление по расписанию и модель прогноза урожайности ещё не подключены.

## Запуск

```powershell
npm install
npm run dev:full
```

Команда запускает frontend и MongoDB API одновременно. Откройте `http://localhost:5173/`.

Можно запускать отдельно:

```powershell
npm run server   # API и MongoDB на http://localhost:3001
npm run dev      # frontend на http://localhost:5173
```

Production-проверка:

```powershell
npm run build
```

## Публикация на Railway

Один Railway-сервис запускает Express API и отдаёт собранный frontend с того же домена. Отдельный frontend-сервис и `VITE_API_URL` не нужны.

1. Создайте проект Railway из репозитория и добавьте в него MongoDB (или используйте доступную извне MongoDB).
2. Для сервиса приложения в **Variables** задайте `MONGODB_URI` ссылкой на строку подключения базы, например `${{MongoDB.MONGO_URL}}` (название сервиса и переменной уточните в Railway). Задайте `NODE_ENV=production` и при необходимости `MONGODB_DB=smartagro`.
3. Карта Leaflet по умолчанию использует спутниковую подложку [Esri World Imagery](https://www.arcgis.com/home/item.html?id=10df2279f9684e4a9f6a7f08febac2a9); рядом есть режим [OpenTopoMap](https://opentopomap.org/about) с рельефом и данными OpenStreetMap/SRTM. Новый API-ключ для этих подложек не нужен. Если спутниковые тайлы недоступны, карта сообщает об этом и показывает OpenTopoMap. При недоступности OpenTopoMap остаётся стандартная OpenStreetMap с явным предупреждением. На карте отображается атрибуция каждого источника, включая лицензию стиля OpenTopoMap CC BY-SA.
4. Опционально укажите `OPENAI_API_KEY` и `OPENAI_MODEL`. OpenAI-ключ используется только сервером.
   Чтобы получать спутниковые индексы по кнопке из CDSE, добавьте `CDSE_CLIENT_ID` и `CDSE_CLIENT_SECRET` **только в Variables backend-сервиса**. Получите OAuth Client в [CDSE Sentinel Hub Dashboard](https://documentation.dataspace.copernicus.eu/APIs/SentinelHub/UserGuides/BeginnersGuide.html) (User Settings → OAuth Clients). Не используйте обычный пароль учётной записи.
5. Railway прочитает `railway.json`: Railpack установит зависимости по `package-lock.json`, выполнит `npm run build`, затем `npm start`. В разделе **Networking** сгенерируйте публичный домен. Проверьте главную страницу и `https://<домен>/api/health` (режим `mongodb`). Если в Railway вручную задана команда сборки, установите `npm run build` или удалите переопределение.

После регистрации поля и расходы сохраняются в MongoDB выбранного ТОО. При повторном входе с другого устройства они загружаются через `/api/fields`. Для существующих регистраций после обновления приложения требуется войти снова, чтобы получить серверную сессию. Локальные поля, ранее записанные в браузер, автоматически не переносятся.

Погода запрашивается сервером у Open-Meteo по координатам выбранного поля (`GET /api/weather?field_id=...`, требуется вход), включает 7 дней и время получения. Последний полученный прогноз хранится в MongoDB: если Open-Meteo недоступен, остаются только ещё не прошедшие дни с пометкой о сохранённом прогнозе. Если пригодных данных нет, отображается ошибка без вымышленных показателей. Индексы доступны после расчёта в CDSE или загрузки измерений с источником (см. ниже). Прогноз урожайности, климатические индексы риска и ожидаемая маржа пока не имеют источника: интерфейс показывает «Нет данных».

### Загрузка NDVI / EVI / NDWI

Выберите сохранённое поле и нажмите **Загрузить CSV** в блоке индексов. В интерфейсе можно скачать пустой шаблон. Формат: `date,index,value,source,cloudCoverPct` — последняя колонка необязательна; разделитель запятая или точка с запятой. Например, `date` задаётся как `YYYY-MM-DD`, `index` — `ndvi`, `evi` либо `ndwi`, `value` — число от −1 до 1, `source` — указание реального поставщика/продукта, `cloudCoverPct` — 0–100. Файл должен содержать **уже полученные измерения среднего значения по полю**: при загрузке CSV приложение не рассчитывает их заново и не проверяет происхождение файла. Не загружайте произвольные значения как спутниковые данные.

После загрузки данные сохраняются в MongoDB для конкретного поля и ТОО. Повторная загрузка строки с теми же датой, индексом и источником обновляет измерение. API: `POST /api/fields/:fieldId/indices/import` с JSON `{"measurements":[{"date":"YYYY-MM-DD","index":"ndvi","value":0.5,"source":"имя поставщика","cloudCoverPct":10}]}`; `GET /api/fields/:fieldId/indices?index=ndvi&period=30d` поддерживает периоды 7d, 30d и 90d. Оба маршрута требуют входа. Карта показывает среднее значение выбранного индекса **для всего поля**, а не растровые зоны внутри поля; при отсутствии измерений показывает «Нет данных». График и HTML-отчёт используют только загруженные значения с датами и источниками.

### Получение из CDSE

Для сохранённого поля с **точным нарисованным контуром** нажмите **Обновить из CDSE** в блоке индексов. Backend переводит координаты полигона в метрическую проекцию EPSG:3857 и отправляет его в [CDSE Sentinel Hub Statistical API](https://documentation.dataspace.copernicus.eu/APIs/SentinelHub/Statistical/Examples.html), получает статистику Sentinel-2 L2A за последние 30 дней и сохраняет средние NDVI, EVI и NDWI в MongoDB. Используются каналы B02, B04, B08 и B11; NDWI здесь — индекс влаги растительности `(B08 − B11)/(B08 + B11)`. В расчёт входят только классы SCL «растительность» и «голая почва»; облака, тени, снег, вода и пиксели без данных исключаются. Шаг сетки соответствует приблизительно 20 м на местности на широте поля. Дневные интервалы с менее чем 30% валидных пикселей или без измерений пропускаются. Процент валидных пикселей **не равен** точной облачности сцены.

`POST /api/fields/:fieldId/indices/sync` требует сессии и проверяет принадлежность поля ТОО. Повторный запрос по тому же контуру доступен не чаще одного раза в 6 часов, чтобы беречь [квоту CDSE](https://documentation.dataspace.copernicus.eu/Quotas.html). При изменении контура старые расчёты CDSE для него больше не отображаются — обновите данные повторно. При недоступности CDSE сохранённые ранее значения остаются, новые не выдумываются. Дата измерения — начало дневного интервала Statistical API, **не точное время отдельного снимка**. Спутниковая подложка Esri — отдельная мозаика изображений; дата её съёмки может отличаться от даты расчёта CDSE. Интеграция CDSE даёт среднее по полигону и график, но пока не загружает растровую карту внутриполевых зон и не выполняет обновление по расписанию.

Если CDSE возвращает ошибку, интерфейс и ответ `/indices/sync` показывают этап (`auth` или `statistics`), HTTP-код CDSE и безопасное описание причины; в Railway Logs ищите строку `CDSE sync failed` с тем же `requestId`. `auth`/401 означает проблему OAuth Client ID/Secret, `statistics`/400 — ошибку параметров расчёта; 429 — ограничение частоты или квота. Не отправляйте Client Secret, Access Token и полный журнал авторизации в чаты или баг-репорты.

Задачи выбранного поля доступны через `GET /api/tasks?field_id=...`, `POST /api/tasks` и `PATCH /api/tasks/:taskId`. Для всех операций требуется серверная сессия пользователя своего ТОО. В интерфейсе можно назначить задаче участок, срок, приоритет и ответственного, отметить её выполненной и вернуть в работу. Состояние сохраняется в MongoDB.

Кнопка «Скачать отчёт» в dashboard формирует HTML-отчёт по выбранному полю: схему внесённого контура, фактический сбор, загруженные индексы за 90 дней и их график (если есть измерения за разные даты), прямые затраты, погодный прогноз с датой получения и открытые задачи. HTML можно открыть в браузере и сохранить как PDF через печать. Если источника данных нет, отчёт указывает это явно; он не подставляет demo-показатели.

Проверка API полей, задач, индексов, погоды и разграничения доступа: `npm test`.

Порт Railway передаётся через `PORT` автоматически. В production сервис не запустится без MongoDB или собранного frontend; временная база в памяти остаётся только для локальной разработки. `MONGODB_URI` и `OPENAI_API_KEY` нельзя добавлять в frontend или публиковать в репозитории.

## Что доступно

- регистрация агронома, выбор ТОО и сохранение полей, границ и расходов в MongoDB;
- спутниковая карта Esri World Imagery и переключаемая топографическая OpenTopoMap, создание и выделение контура поля без дополнительного API-ключа;
- фактический сбор и расчёт урожайности на основе ручного ввода агронома;
- задачи по полям: создание со сроком, приоритетом, участком и ответственным, отметка выполнения и сохранение в MongoDB;
- HTML-отчёт по выбранному полю с источниками и временем формирования;
- прогноз погоды Open-Meteo на 7 дней по координатам выбранного поля, дата получения и сохранённый прогноз при сбое;
- загрузка датированных измерений NDVI/EVI/NDWI из CSV и график по выбранному полю без искусственных значений;
- получение средних NDVI/EVI/NDWI по контуру поля из CDSE Sentinel-2 L2A при настроенных OAuth-ключах;
- учёт прямых затрат и изменение цены топлива или зерна;
- AI-чат с контекстом поля и явным сообщением об отсутствующих прогнозных данных;
- запрос геолокации пользователя для отображения его местоположения на карте.

Включён локальный режим входа без сервера, но его поля хранятся только в браузере. Для работы с реальными полями используйте зарегистрированный аккаунт и MongoDB.

## Авторизация и MongoDB

До входа приложение показывает отдельный экран авторизации. Можно зарегистрировать агронома, выбрать ТОО или открыть локальный режим без регистрации.

Файл `.env.example` подготовлен для настройки. URI используется только backend; его нельзя размещать во frontend или коммитить в git.

Backend подключается к MongoDB, автоматически создаёт базу `smartagro` и три ТОО без полей, поддерживает регистрацию и вход. Количество полей считается из MongoDB. Геолокация пользователя показывает его положение, а погода берётся только по координатам выбранного поля. Для точного отображения полей нужно нарисовать или загрузить их реальные границы; при отсутствии контура карта отмечает приблизительное положение.

## AI-чат

Ключ нельзя размещать во frontend-коде. На backend он хранится в переменной окружения:

```env
OPENAI_API_KEY=...
```

Frontend обращается к backend endpoint `/api/ai/chat`. Без ключа доступен ограниченный rule-based ответ.

AI получает только данные поля пользователя из MongoDB, сохранённый прогноз погоды и последние измерения индексов с датой и происхождением (расчёт CDSE либо CSV пользователя). Отсутствующие данные и модель урожайности не подменяются демонстрационными показателями. Происхождение CSV не считается независимо проверенным. Вопросы вне работы хозяйства отклоняются.
